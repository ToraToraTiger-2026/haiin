# 01. 概要

## 配員管理ツールとは

コンサルティングチームの配員を、**日単位**で管理する個人用の Web アプリ。
期初計画の必要工数と、現在の配員を突き合わせて、次を見える化する。

- どのクライアントに、何時間足りないか（不足ビュー）
- 誰が、いつ空いているか（空きビュー）

不足を埋める配員案は、自動で提案できる（貪欲法。最適解は保証しない）。

- 公開URL: https://toratoratiger-2026.github.io/haiin/
- リポジトリ: https://github.com/ToraToraTiger-2026/haiin（公開リポジトリ。**実データは入れない**）
- 利用者: 個人（1人）。ログインや共有の仕組みはない
- 費用: 無料（GitHub Pages のみ。サーバーも外部サービスもない）

## 特徴

| 特徴 | 内容 |
|---|---|
| ブラウザだけで動く | 素の HTML / CSS / JavaScript（ES modules）。ビルドなし |
| データはブラウザの中 | すべて IndexedDB に保存する。サーバーや外部への通信はない |
| 保存しない集計 | 負荷・不足・空き・Gap は、保存せず、表示のたびに計算する |
| 下書きで試せる | 本番のコピー（下書き）の上で配員を動かし、影響を確認してから本番へ反映する |
| Excel は使わない | 取り込み・書き出しは CSV と JSON |

## 画面

画面は10個。上部のメニューから切り替える（URL のハッシュ `#/shortage` などで直接開ける）。

| 画面 | 内容 |
|---|---|
| 不足ビュー | クライアント × 月の、必要工数・配員・不足・チーム内の空き。月ごとの Gap。セルを押すとメンバー別・日別の内訳 |
| 空きビュー | メンバー × 週（または日）の空き時間と上限超過 |
| 配員グリッド | メンバー × 日の配員。配員ルールの追加・編集・削除・ロック |
| 需要入力 | クライアント × 月の「現在の需要」を入力する。計画との差と変更理由を残す |
| シナリオ | 下書きの作成・確定・破棄、本番との比較、配員案の自動提案 |
| 応援要請レポート | 不足の一覧と、チーム外の応援が必要な目安。CSV 出力・印刷 |
| マスタ | メンバー、クライアント、チーム編成、上限の例外、期 |
| インポート/エクスポート | JSON バックアップ、CSV の書き出し・取り込み |
| 変更履歴 | 変更の記録（日時・操作者・対象・変更前後） |
| データ | ダミーデータの生成、全データの削除、テーブルごとの件数 |

画面の上部には、**シナリオ**の選択（本番／下書き）と、**操作者**の名前の入力欄がある。

## 基本の考え方

### 時間の単位
すべて「時間」。上限（Cap）と配員は1日あたりの時間、需要は月あたりの時間。

### 3つの量
| 量 | 意味 |
|---|---|
| 需要（Demand） | クライアント × 月の必要工数。期初の**計画**（固定）と、**現在**の値（変更可）がある |
| 配員（Allocation） | メンバー × クライアント × 日の配員時間 |
| 上限（Cap） | メンバー × 日に配員できる時間。標準上限（平日）と、日ごとの例外（休暇・祝日・時短） |

### 3つの指標
| 指標 | 意味 |
|---|---|
| 不足（Short） | 需要 − 配員（クライアント × 月）。配員が上回っても負にはしない |
| 空き（Free） | 上限 − 配員（メンバー × 日）。月の空きは、その月の日ごとの空きの合計 |
| 上限超過（Over） | 配員 − 上限（メンバー × 日）。超過した日は、空きを 0 として数える |

計算式は [03-data-model.md](03-data-model.md) を参照。

### 配員の入れ方
日ごとに入力するのではなく、**配員ルール**（メンバー × クライアント × 期間 × 1日あたりの時間）を入力する。
保存すると、ルールから日単位の配員に展開される。ルールを編集・削除すると、展開された配員も入れ替わる。

### 本番と下書き（シナリオ）
- **本番**が現在の正式な配員。
- **下書き**は本番のコピー。下書きの上で配員を動かしても、確定するまで本番に影響しない。
- 確定すると、下書きの内容で本番が置き換わり、下書きは消える。

## 利用の流れ（例）

```
1. マスタ/データの準備      メンバー・クライアント・期・チーム編成を登録（またはCSV取り込み）
2. 計画需要の取り込み       期初の計画需要をCSVで取り込む（画面からは編集できない）
3. 配員の入力               配員グリッドで配員ルールを追加
4. 不足・空きの確認         不足ビュー、空きビュー
5. 需要の変更               需要入力で、遅延などによる現在の需要を更新（変更理由つき）
6. 再配員の検討             シナリオで下書きを作る → 手で動かす／自動提案 → 影響を比較 → 確定
7. 応援要請                 応援要請レポートを CSV か印刷で出す
8. バックアップ             JSON を定期的に書き出す
```

## 用語

| 用語 | 意味 |
|---|---|
| 期 | 計画の単位（例：2026年4月〜2027年3月）。月の一覧は期から決まる |
| 計画需要（plan_demand） | 期初の必要工数。固定 |
| 現在の需要（current_demand） | 遅延や変更を反映した必要工数。シナリオごと |
| チーム編成（team_members） | クライアントごとの担当メンバー。シナリオごと |
| 配員ルール（assignment_rules） | 期間と1日あたりの時間による配員の入力単位 |
| 配員（allocations） | ルールから展開された日単位の配員 |
| 上限の例外（capacity） | 日ごとの上限の例外。祝日は上限 0 を入れる |
| ロック | 自動提案で動かさない配員ルール |
| Gap | 月ごとの「不足の合計 − 空きの合計」。正なら、他チームへの応援が必要 |
| 応援が必要な目安 | 不足 −（チーム内の空き）。正の部分 |
