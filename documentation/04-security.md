# 04. セキュリティとデータ保護

このツールは、サーバーを持たず、データをすべて**利用者のブラウザの中**にだけ置く。そのため、守るべき点は次の3つ。

1. 実データを、公開リポジトリに入れない
2. ブラウザの中のデータを、失わない（バックアップ）
3. ブラウザの中のデータを、他人に見せない

## 1. 公開リポジトリの扱い

- リポジトリは**公開**で、GitHub Pages がリポジトリ全体を配信する。
- **実データ（メンバー名、クライアント名、工数、配員など）は、リポジトリに入れない。** コード、ダミーデータ、ドキュメントだけを入れる。
- `dummy.js` のダミーデータは、実在の名前・数値を使わない。シード付きの乱数なので、毎回同じ結果になる。
- 書き出した JSON バックアップや CSV には実データが入る。**コミットしない**。`.gitignore` には、これらを除外する指定がない（`Thumbs.db`、`.DS_Store`、`*.log` だけ）ので、リポジトリの中に置かない。書き出したファイルは、リポジトリの外のフォルダに保存する。
- 秘密情報（キー、パスワードなど）は、このプロジェクトには存在しない。

## 2. 外部との通信

- コードに、通信（`fetch` など）の処理はない。**実行中に、データが外部へ送られることはない。**
- 外部ライブラリ・CDN・フォント・解析ツールも使っていない。
- ファイルの配信だけが GitHub Pages を通る。

## 3. ブラウザの中のデータ

- データは IndexedDB に、**暗号化されずに**保存される。同じブラウザのプロファイルを使える人は、開発者ツールなどで読める。
- 他の人と共有するパソコンでは使わない。または、使い終わったら「データ」画面で全データを削除する（先に JSON バックアップを書き出す）。
- 保存場所は、ブラウザごと・アドレス（オリジン）ごとに別。別のサイト（別のドメイン）からは読めない。
- 次のときに、データが消える。バックアップが唯一の復旧手段になる。
  - ブラウザの「サイトデータ」「閲覧履歴とキャッシュ」を削除したとき
  - 「全データを削除」を押したとき
  - JSON を取り込んで、全データを置き換えたとき
  - ブラウザが、容量不足などで、サイトのデータを自動的に消すことがある（ブラウザの仕様による）
  - シークレット（プライベート）ウィンドウを閉じたとき
- バックアップの方法と手順は [07-operations-runbook.md](07-operations-runbook.md) を参照。

## 画面の安全性

- 画面の要素は `ui.js` の `h()` で作り、文字列は常にテキストとして挿入する。`innerHTML` は使っていない。取り込んだ CSV や JSON の文字列が、そのまま HTML として解釈されることはない。
- このサイトには、Content-Security-Policy（CSP）の設定がない。外部のスクリプトを読み込まないので、現状では実害は想定しにくいが、将来、外部のライブラリを足すときは検討する。
- 取り込みの検査：
  - CSV：見出し、数値・日付（`YYYY-MM-DD`）・月（`YYYY-MM`）・真偽値の形式、必須項目、参照先（クライアント・メンバー・期）の存在を確認する。エラーが1件でもあれば取り込まない。
  - JSON：`app` が `haiin` か、各テーブルが配列かを確認する。**中の行の値の形式までは検査しない**ので、このツールが書き出したファイルだけを取り込む。

## 操作者の名前

画面上部の「操作者」は、変更履歴に残す名前で、認証ではない。誰でも書き換えられる。本人確認や監査には使えない。

## やってはいけないこと

- 実データを含むファイル（バックアップ JSON、CSV、スクリーンショット）を、このリポジトリに置く・コミットする。
- 実データを含む状態で、公開 URL のページ以外（他人のパソコンなど）にデータを移す。
- 取り込むとデータが置き換わる JSON を、バックアップをとらずに取り込む。
