# 05. フロントエンド・リファレンス

素の ES modules で、JavaScript が26ファイル・約2,850行（`js/` と `js/views/`）、CSS が2ファイル・約150行。ビルドなし。

## モジュール一覧

| ファイル | 責務 |
|---|---|
| `app.js` | 起動。メニューを作り、ハッシュ（`#/<画面名>`）で画面を切り替える。シナリオ選択と、下書き表示中のバナーを更新する。画面の表示に失敗したらエラーを出す |
| `db.js` | IndexedDB のラッパー。`STORES`、`PROD`、`getAll` `getAllByIndex` `get` `count` `putMany` `deleteKeys` `deleteByIndex` `replaceScenario` `clearStores` `countAll` |
| `state.js` | 表示中のシナリオと期（sessionStorage）。`notifyScenariosChanged()` で画面全体に通知する |
| `changelog.js` | 操作者（localStorage）、`recordChange`、`putLogged`、`deleteLogged` |
| `dates.js` | 日付の計算。すべて `YYYY-MM-DD` の文字列。`today()` だけがローカル時間、ほかは UTC 基準 |
| `calc.js` | 集計の純関数（[03](03-data-model.md) の計算式） |
| `expand.js` | `expandRule`（ルール → 日単位）、`findOverlap`（重なり）、`checkOverload`（上限超過）、`rebuildRules`（日単位 → ルール）、`newRuleId` |
| `scenario.js` | `createDraft`、`discardDraft`、`commitDraft`、`createDraftWithData`、`loadScenarioData`。`SCOPED`（シナリオ別の4テーブル） |
| `solver.js` | 自動提案 `solve`（下に詳細）。外部ソルバーは使わない |
| `worker.js` | `solve` を Web Worker で動かし、進捗を返す |
| `propose.js` | `runSolver`（Worker または画面のスレッドで実行）と、`proposeDraft`（結果を新しい下書きに保存） |
| `periodctx.js` | 表示する期の決定（選択中 → 今日を含む期 → 最後の期）と、期の選択欄 |
| `report.js` | `buildShortageRows`（不足一覧の行）、不足一覧と Gap の CSV 出力 |
| `io.js` | `SCHEMA`（列の定義）、`IMPORTABLE`、CSV の解析と生成、JSON バックアップの生成と検証 |
| `dummy.js` | `buildDummy`、`loadDummy`（全テーブルを消して、ダミーデータを書き込む） |
| `ui.js` | `h()`（要素の作成）、`fmt`（時間の表示）、`setStatus`、`openDialog`、`field`、`download` |

### 依存の向き

```
app.js ─ views/* ─ calc / expand / scenario / propose / report / io / periodctx
                 └ db / changelog / state / ui / dates
propose ─ scenario / solver(worker) / expand
scenario ─ db / changelog / expand
calc, solver ─ dates          （純関数。画面や DB に依存しない）
```

`calc.js` `expand.js` `solver.js` `io.js` は画面から独立しているので、`tests.html` で単体で試せる。

## 画面

### 不足ビュー（`views/shortage.js`）
- クライアント × 月の表。各セルに、不足（または「充足」）、必要・配員、チーム内の空きを出す。不足があるセルは赤。
- 下に、月ごとの「不足合計」「空き合計（全メンバー）」「Gap」。
- 期の選択、「不足のあるクライアントだけ」の絞り込み、CSV 出力、印刷。
- セルを押すと、メンバー別の内訳（開くと日ごとの上限・配員・空き）。チーム外のメンバーには「（チーム外）」が付く。
- 期が1つも登録されていないときは、案内の文を出す。

### 空きビュー（`views/free.js`）
- メンバー × 週（13週）または日（28日）の空き時間。上限を超える期間は赤で「超過」を併記する。
- 「すべてのメンバー」か「特定クライアントのチームのみ」で絞る。◀前へ／今週／次へ▶、日付の指定。
- セルを押すと、日ごとの上限・配員・空き・超過・内訳。

### 配員グリッド（`views/grid.js`）
- メンバー × 日（28日）の配員合計。赤＝上限超過、灰＝上限 0（休日・休暇）。**下書きでは、本番と配員が違う日を青枠で示す**。
- セルを押すと、その日の内訳。ルールの編集、その人への配員の追加ができる。
- 下に配員ルールの一覧（メンバー・クライアントで絞り込み。先頭200件）。ロックのチェック、編集、削除。
- 配員ルールのダイアログ：
  - クライアントを選ぶと、そのチームのメンバーだけが選べる。チーム編成がないクライアントは、エラーになる。
  - エラー（保存できない）：開始日・終了日が不正、終了日が開始日より前、時間/日が 0 以下、期間が重なる既存ルールがある。
  - 警告（保存はできる）：上限を超える日がある（先頭8日を表示）。
  - 「保存した場合の影響」として、変わるクライアント × 月の配員・不足を事前に表示する（先頭12件）。
- 削除すると、そのルールと、展開された配員が消える。

### 需要入力（`views/demand.js`）
- クライアント × 月。各セルに、期初の計画（固定）、現在の需要の入力欄、計画との差（青）、変更理由がある印（※）。
- 値を変えると、変更理由を入れるダイアログが出る。**計画と違う値にするときは、変更理由が必須**。
- 計画需要（`plan_demand`）は、**画面からは編集できない**。CSV または JSON で取り込む（ダミーデータには含まれる）。
- 下に、計画の合計と、現在の需要の合計。

### シナリオ（`views/scenario.js`）
- シナリオの一覧（名称、種別、作成者、作成日時）。「表示する」「確定（本番へ反映）」「破棄」。
- 「本番から下書きを作る」。名前を付けて作ると、その下書きに切り替わる。
- 下書きを表示しているときは、**影響の確認**を出す。
  - 指標：不足の合計、不足のあるクライアント × 月、上限超過の合計、上限超過のあるメンバー × 日（本番 → 下書き、差）
  - 不足・配員が変わったクライアント × 月（変化の大きい順に先頭30件）
  - 上限超過が変わったメンバー（先頭30人）
- 「配員案を自動提案」：下の節を参照。

### 応援要請レポート（`views/report.js`）
- 期、期間（月の範囲）、クライアントの絞り込み（Ctrl で複数選択。選ばなければ全クライアント）、「不足のある行だけ」。
- 不足一覧（必要、配員済み、不足、チーム内の空き、チーム外の応援が必要な目安）と、月ごとの Gap。
- Gap は、選んだクライアントの不足だけで数える（空きは全メンバーの合計）。
- 不足一覧と Gap の CSV 出力、印刷。表示中のシナリオ（本番／下書き）が対象。

### マスタ（`views/master.js`）
5つのタブ。変更は変更履歴に残る。

| タブ | 内容 | 削除の制限 |
|---|---|---|
| メンバー | 氏名、標準上限（時間/日）の編集、追加、削除 | 配員ルールかチーム編成で使われていると削除できない。削除すると、そのメンバーの上限の例外も消える |
| クライアント | 名前、有効の編集、追加、削除 | 配員・チーム編成・需要で使われていると削除できない（「有効」を外す） |
| チーム編成 | クライアントごとにメンバーのチェック、役割（任意） | 配員ルールが残るメンバーを外すときは確認。ルールは消えない。**表示中のシナリオの**チーム編成を編集する |
| 上限の例外 | メンバーごとの日別の上限。祝日・全社休日の**一括登録**（日付を1行に1つ、全メンバーに同じ上限） | |
| 期 | 期名、開始日、終了日の編集、追加、削除 | 削除しても、その期の計画需要は残る |

### インポート/エクスポート（`views/io.js`）
- JSON：全テーブルの書き出し（`haiin-backup-<日付>.json`）。取り込みは、現在と取り込み後の件数を見せ、確認の上で**全データを置き換える**。
- CSV の書き出し：全11テーブルを選べる（`haiin-<テーブル名>-<日付>.csv`、UTF-8 BOM つき）。
- CSV の取り込み：7テーブル（下記）。プレビュー（先頭10行）、エラー表示（先頭20件）。同じキーの行は上書き、ない行は追加で、既存の他の行は消えない。
- 配員ルール・配員・シナリオ・変更履歴は、CSV では取り込めない（JSON で取り込む）。

| 取り込める CSV | 参照の確認 |
|---|---|
| `members` `clients` `periods` | なし |
| `plan_demand` | クライアント、期 |
| `current_demand` | クライアント |
| `team_members` | クライアント、メンバー |
| `capacity` | メンバー |

CSV の見出しは、日本語（書き出したときの見出し）でも英語のキーでも読める。`scenario_id` が空なら本番として扱う。`clients` の `active` の列がなければ、有効として扱う。

### 変更履歴（`views/history.js`）
新しい順に先頭200件。テーブルと、操作者・対象IDの文字で絞り込める。

### データ（`views/data.js`）
- 「ダミーデータを生成」：**既存のデータをすべて消して**、メンバー30人・クライアント50社のダミーデータを作る（確認あり）。
- 「全データを削除」：ブラウザ内のデータをすべて削除（確認あり）。
- テーブルごとの件数。

## 自動提案（`solver.js`、`propose.js`）

**貪欲法。最適解は保証しない。**

### 入力（画面）
| 項目 | 内容 |
|---|---|
| 下書きの名前 | 結果を保存する新しい下書きの名前 |
| モード | **A**：既存配員は動かさず、チームメンバーの空きだけで埋める。**B**：ロックしていない既存配員の再配分も許す（必要工数を超えているクライアントの余剰を、不足側へ付け替える） |
| この日以降の配員だけ動かす | 既定は今日。これより前の日は動かさない |
| 優先度（低・中・高 = 1・2・3） | 不足の解消（w1、既定は高）、変更の少なさ（w2、既定は中）、負荷の公平さ（w3、既定は低） |
| チーム外のメンバーも候補にする | 使った場合は、下書きのチーム編成に「応援(自動提案)」の役割で加える |

対象の月は、選択中の期の月。ロックした配員ルールは動かさない（負荷には数える）。

### 手順
1. 対象の月のうち、不足があるクライアント × 月を、**不足の大きい順**に処理する。
2. まず、そのクライアントのチームのメンバーで埋める。許可していれば、次にチーム外のメンバーで埋める。
3. 1回の配員ごとに、候補（メンバー × 日）を評価して、最も良いものを採る。
   - 採用の条件：`w1 − w2 × 0.25 × (変更の大きさ) > 0`（変更の大きさは、すでにそのクライアントへ配員している日は 1、新しい日は 1.25、付け替えは 2）
   - 順位：上の値 `− w3 × 0.5 ×（配員後のそのメンバーの月の稼働率）+ 0.01 ×（配員量）`。チーム外は、すでに加えたメンバーでなければ 0.3 を引く
4. 不足が埋まるか、候補がなくなるまで続ける。

### 制約
- 日ごとの配員は、上限以内。
- クライアントの月の配員は、必要工数以内（不足を埋める分だけ配員する）。
- ロックした配員は動かさない。
- 土日や上限 0 の日には配員しない（その日の空きがないため）。

### 結果
- 動かしてよい配員を、`rebuildRules` で配員ルールに組み直す。同じメンバー × クライアントで、時間が同じ日が続く範囲を1つのルールにまとめる（平日は、金→月をまたいで続くとみなす。土日の配員は別のルールにする）。
- 新しい下書きとして保存し、その下書きに切り替える。本番は書き換えない。
- 画面に、不足の合計（前 → 後）、配員を変えた時間、チーム外から加えた組の数、解消できなかった不足を出す。解消できなかった不足は CSV に出せる（応援要請の根拠）。

## 見た目の決まり
- 赤は、**不足と上限超過だけ**に使う。差分は青系で示す。
- 下書きを表示している間は、画面上部にバナーを出し、本番と区別する。
- 印刷時は、操作部品（`no-print`、選択欄、検索欄）を隠す。

## 同期が必要な箇所

別々の場所に同じ前提が書かれていて、片方だけ直すと壊れる。

| 変えるもの | 同時に直す場所 |
|---|---|
| テーブルの追加・列の追加 | `db.js` の `STORES`、`io.js` の `SCHEMA`（と、取り込めるものなら `IMPORTABLE`、`views/io.js` の `REFS`）、`dummy.js` の `buildDummy`。構成を変えるときは `DB_VERSION` を上げ、移行の処理を書く |
| シナリオ別にするテーブル | `scenario.js` の `SCOPED` と `retarget`、`db.js` の `scenario_id` のインデックス |
| 自動提案の重み・係数 | `solver.js` の `KAPPA` `MU`、`views/scenario.js` の優先度の既定値（`LEVELS`、`w1` `w2` `w3`） |
| 不足・空き・Gap の定義 | `calc.js`。表示は `views/shortage.js` `views/free.js` `views/report.js` `views/scenario.js`、CSV は `report.js`。`tests.html` `tests_step4.html` も確認する |
| ローカル保存のキー | `changelog.js`（`haiin.actor`）、`state.js`（`haiin.scenario` `haiin.period`） |
