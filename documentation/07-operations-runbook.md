# 07. 運用手順書

日常の使い方と、バックアップ・復旧。**データはブラウザの中にだけある**ので、バックアップが唯一の守りになる。

## 最重要：バックアップ

「インポート/エクスポート」→「JSONを書き出す」で、全テーブルを `haiin-backup-<日付>.json` として保存する。

- **こまめに書き出す。** 特に、次の前には必ず書き出す。
  - 下書きを本番へ確定する前
  - JSON や CSV を取り込む前
  - 「ダミーデータを生成」「全データを削除」を押す前
  - ブラウザのデータ削除や、ブラウザの入れ替え・パソコンの交換の前
  - このツールのコードを更新して公開する前
- **保存先は、このリポジトリの外**にする。実データを含むので、コミットしない。
- 古いバックアップも、数世代残しておく。

## 日常の作業

### 1回目の準備
1. 「マスタ」で、メンバー（氏名・標準上限）、クライアント、期、チーム編成を登録する。または、CSV で取り込む（取り込みの順番は下記）。
2. 祝日・全社休日を、「マスタ」→「上限の例外」の一括登録で入れる（上限 0）。休暇・時短はメンバーごとに入れる。
3. 期初の計画需要を、CSV（`plan_demand`）で取り込む。
4. 配員グリッドで、配員ルールを入れる。

**CSV を取り込む順番**（参照先が先に必要）：メンバー・クライアント・期 → 計画需要・現在の需要・チーム編成・上限の例外。

### 需要が変わったとき
「需要入力」で、現在の需要を書き換え、変更理由を入れる（計画と違う値には変更理由が必須）。

### 再配員を検討するとき
1. 「シナリオ」で、本番から下書きを作る。名前は分かるものにする（例：11月の再配員案）。
2. 下書きの上で、配員グリッドから配員を動かす。または、「配員案を自動提案」を使う（結果は新しい下書きになる）。
3. 「影響の確認」で、不足・上限超過がどう変わるかを見る。
4. よければ「確定（本番へ反映）」。やめるなら「破棄」。

確定すると、**本番の需要・チーム編成・配員ルール・配員が、下書きの内容で置き換わる**。下書きを作ってから本番に加えた変更も、下書きの内容に置き換わる。確定の前にバックアップをとる。

### 応援を要請するとき
1. 「応援要請レポート」で、期間とクライアントを選ぶ。
2. 「不足一覧をCSV出力」「GapをCSV出力」、または「印刷」。
3. 「チーム外の応援が必要な目安」は目安の値（同じメンバーが複数のチームに入っていると、重複して数えられる）。

## 復旧

### バックアップから戻す
1. 「インポート/エクスポート」→「JSONを取り込む」で、バックアップのファイルを選ぶ。
2. 現在の件数と、取り込み後の件数が表に出る。内容を確認する。
3. 「置き換えて取り込む」を押す。**現在のデータは、すべてバックアップの内容に置き換わる。**

- `app` が `haiin` でないファイルは、取り込めない。
- 取り込みの途中でエラーになると、一部のテーブルだけが入った状態になることがある。もう一度、同じバックアップを取り込み直す。

### 別のブラウザ・別のパソコンへ移す
1. 元のブラウザで、JSON を書き出す。
2. 移し先で公開URLを開き、「JSONを取り込む」。

### 公開URLとローカルのデータは別
`localhost`（Live Server）で入れたデータは、公開URLでは見えない。逆も同じ。移したいときは、JSON で書き出して取り込む。

## 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 画面が空、または「期が登録されていません」と出る | 期が未登録。「マスタ」→「期」で登録するか、「データ」でダミーデータを生成する |
| データが消えた | ブラウザのデータ削除、別のアドレスで開いている、別のブラウザで開いている、シークレットウィンドウ。バックアップから戻す |
| 配員ルールを保存できない（赤いエラー） | 同じメンバー・クライアントで期間が重なるルールがある。表示された期間のルールを編集する。または、そのクライアントにチーム編成がない。「マスタ」→「チーム編成」で登録する |
| 上限を超える警告が出る | 保存はできる。配員が上限を超える日がある。祝日・休暇の登録漏れもよくある原因 |
| メンバー・クライアントを削除できない | 配員・チーム編成・需要で使われている。クライアントは「有効」を外す |
| 自動提案が「解消できなかった不足」を残す | 空きが足りない、または制約で入らない。優先度を変える、モード B を試す、チーム外を候補にする、開始日を前にする。残った分が応援要請の根拠になる |
| CSV を取り込めない | エラーの一覧を確認する（見出し、数値・日付の形式、参照先がないなど）。参照先（メンバー・クライアント・期）を先に取り込む |
| CSV の文字が化ける | UTF-8 で保存し直す。このツールが書き出す CSV は UTF-8（BOM つき） |
| 変更履歴が多すぎる | 画面は新しい順に200件まで。テーブルや、操作者・対象IDで絞り込む |
| 下書きのまま本番に見えない | 画面上部の「シナリオ」が、本番か下書きかを確認する。下書き表示中は、バナーが出ている |
| 動きが遅い | 配員グリッドのルール一覧は200件まで表示する。自動提案は、画面とは別のスレッド（Web Worker）で動く |

## ブラウザのデータを消したいとき

1. 先に、JSON を書き出す（バックアップ）。
2. 「データ」→「全データを削除」。
3. または、ブラウザの設定で、このサイトのデータを削除する。

操作者の名前（localStorage）も、サイトのデータの削除で消える。
